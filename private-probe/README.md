# Private ByteBans compatibility probe

This directory contains test infrastructure only. Its plugin and Node client are not part of the releasable ByteBans JAR and must not be uploaded to Modrinth.

Build ByteBans with `mvn install`, then run `mvn -f private-probe/pom.xml package`. The test-only plugin depends on the real ByteBans plugin. On startup it inserts temporary probe punishments, dispatches Bukkit login, chat and movement events for synthetic non-staff and operator players, removes those punishments, and writes `plugins/ByteBansPrivateProbe/results.json`. These checks exercise the live Paper event bus and ByteBans listeners. They do **not** prove that an actual Minecraft client connected.

`matrix.json` pins exact Paper builds, binary SHA-256 hashes and Java runtimes for fifteen Minecraft versions from 1.21 through 26.3, each in online and offline mode. Four of these versions have experimental Paper builds and are labeled as such. `python private-probe/run_matrix.py --list` shows the 30 pinned targets without contacting the server. `python private-probe/run_matrix.py --target paper-1.21.4-online-synthetic` creates one selected isolated server from the pinned pair of JARs, verifies the Paper and both plugin binary hashes, checks the plugin's startup log, reads the JSON result, saves a receipt under `private-probe/runs/`, and stops the server. Use `--jar` and `--source-revision` to bind an exact frozen candidate when the current Maven output has changed. Running without `--target` walks the whole matrix sequentially. The runner preserves every managed instance and world for later inspection. It uses ports 27200–27299, 4 GB RAM and four CPU cores, one server at a time.

For a real protocol check, install the Node client with `npm ci --ignore-scripts` in `private-probe/client/`, then run `python private-probe/run_offline.py`. This creates a separate loopback-bound offline-mode Paper 1.21.4 target and opens an SSH loopback tunnel. Mineflayer joins as two non-operator test users. The script tests actual login, existing-session kick, shared-IP rejection, shared-IP chat mute and freeze/unfreeze movement. A console-only command in the separate testing helper measures the server's authoritative position; Mineflayer's predicted local position is recorded only as context. The script saves its result and stops the server. Use `--reuse <managed-id>` to retest a stopped instance only when its owner, mode, build, port and both JAR hashes match. It never opens the game port on the LAN or internet.

No Microsoft-authenticated bot is available for online-mode protocol login. The online-mode targets therefore use only synthetic event checks; they must be labeled as such. The offline TCP run supplies complementary real-client evidence, but does not by itself establish authenticated-session behavior. Failure or missing results do not imply compatibility.

`admin_web_http_probe.py` is a separate private HTTP/SQLite smoke for an already-running test instance with `admin_web.enabled: true`. Run it only inside that container's network namespace on the test host, supplying the managed instance ID and frozen ByteBans SHA-512. It reads the private token file without printing the token, checks login, Host and CSRF rejection, then creates and undoes a note for a random unused UUID while verifying the database audit. Restore the test instance's original config and stop the server afterward. Never run this probe against a production database.

Run `python private-probe/summarize.py` to regenerate the local 30-target progress report for the frozen feature JAR. It counts a target as passing only when its latest matching receipt includes all required event checks, matching deployed JAR and Paper hashes, clean startup diagnostics, and a stopped retained instance. Real-client and web-panel receipts remain separate evidence.

`python private-probe/release_gate.py --dry-run` is the ByteBans-specific release gate. It reads the exact frozen JAR and source revision, all thirty pinned matrix targets, separate real-client and admin-web receipts, and `release-changelog.md`. It writes a local `runs/release-dry-run.json` with every blocker. A missing, failed, stale, or mismatched mode blocks the entire release; a Paper version qualifies only after both its online- and offline-mode synthetic targets pass. These checks do not establish Bukkit, Spigot, or Purpur compatibility, so the proposed Modrinth version lists Paper only. The existing ByteBans 1.0.0 release is never edited or deleted.

The substantial AI-written code and release text are documented in `runs/PROVENANCE.md`; the new feature set may make the project primarily AI-derived despite its original user-written foundation. Copy `ai-review.template.json` to ignored `runs/ai-review.json` only after a human project-level eligibility decision. Record the review basis and confirm the required code, text, and optional Discord data disclosures. The gate requires a truthful finding that the project remains eligible; it is deliberately closed while the review is missing or finds otherwise. Do not describe this update as mere tab completion. No AI-generated icon or gallery media belongs in this release.

Only after explicit owner instruction to publish, a passing dry-run, and that human review, run `python private-probe/release_gate.py --upload --user-approved-upload`. This uses a dedicated ByteBans JAR uploader, checks that the existing 1.0.0 version retains its pinned hash and compatibility metadata, creates at most one new 1.1.0 beta version, reads it back to verify the exact SHA-512/SHA-1, Paper loader, Minecraft versions, changelog, and environment, then saves ignored `runs/publication.json`. An existing identical upload is verified idempotently; conflicting metadata stops the command. The default dry-run never opens an upload client. Run `python -m unittest discover -s private-probe -p test_release_gate.py -v` to test these gate behaviors without network writes.
